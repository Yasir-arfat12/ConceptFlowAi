# ConceptFlow AI – DB Schema Reference

## Tables

| Table | Purpose |
|-------|---------|
| `schema_migrations` | Migration version tracking |
| `users` | User accounts |
| `topics` | Predefined topic catalog |
| `topic_concepts` | Concept content for each predefined topic |
| `learning_sessions` | Per-user learning sessions |
| `session_concepts` | Per-learner snapshot of concept content |
| `checkpoints` | One checkpoint per session_concept |
| `checkpoint_responses` | Student answers with scores and feedback |
| `doubt_threads` | One thread per (session, concept) |
| `doubt_messages` | Individual messages in doubt threads |
| `ai_call_log` | AI call metadata (no prompt text) |

## Key Constraints

- `session_concepts`: `UNIQUE(session_id, position)` — one concept per position per session
- `session_concepts`: Partial unique index on `status='active'` per session — at most one active concept
- `doubt_threads`: `UNIQUE(session_id, session_concept_id)` — one thread per concept per session
- `checkpoints`: `UNIQUE(session_concept_id)` — one checkpoint per concept

## ID Strategy
All primary keys are `UUID` generated by `gen_random_uuid()` (PostgreSQL `pgcrypto`).

## Indexes
- All foreign keys are indexed
- `users.email` — for fast login lookup
- `learning_sessions.user_id`, `status`
- `session_concepts.session_id`
- `doubt_messages.thread_id`
- `checkpoint_responses.checkpoint_id`, `user_id`
